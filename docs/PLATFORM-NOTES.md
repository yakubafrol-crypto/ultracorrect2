# Платформенные решения — 01a

## Подпись и сборка

- Bundle ID: `local.ultracorrect.mac`, сохранён от 0.1.x.
- Идентичность: `UltraCorrect Local Development`, SHA-1 `28107DCFD48A5B3B21DC6726144ACFFDDCE44E0A`. Приватный ключ остаётся в Связке, не читался и не экспортировался.
- Designated requirement: `identifier "local.ultracorrect.mac" and certificate leaf = H"28107dcfd48a5b3b21dc6726144acffddce44e0a"`.
- Пустые UltraCorrect и UCTestHost: macOS 15+, arm64, Swift 6, Hardened Runtime, без App Sandbox. `LSUIElement=true` у UltraCorrect.
- `scripts/build.sh` собирает и подписывает оба приложения этой идентичностью. Номер локальной сборки растёт в игнорируемом `work/build-number`; в CI используется `31 + GITHUB_RUN_NUMBER`. `CFBundleVersion` берётся из `CURRENT_PROJECT_VERSION`.
- CI намеренно собирает без подписи (`CODE_SIGNING_ALLOWED=NO`), как предписано ТЗ. Ad-hoc подписи у распространяемой сборки нет; приложения в этом prerelease не распространяются.
- На исходном Mac проверено повторное использование существующей идентичности. Создание новой идентичности на другом Mac описано скриптом Security.framework (ключ сразу в Связке, сертификат 10 лет, доверие только для code signing); ветка создания не выполнялась, чтобы не менять действующую подпись. Проверена компиляция помощника.

## Системные раскладки

`uc-layout-dump` выполняет TIS/UCKeyTranslate синхронно на главном потоке. Настройки системы не менялись.

| ID фикстуры | Раскладка | Записей | Включена при снятии |
|---|---|---:|---|
| en | ABC | 428 | нет |
| us | U.S. | 428 | да |
| ru | Русская | 436 | да |
| ru-pc | Русская — ПК | 436 | нет |

«Установлена» и «включена» различаются: TIS предоставил все четыре таблицы без изменения пользовательского списка источников. Таблицы включают keycode и Shift/Option, пометки dead key. Caps Lock для букв обрабатывается отдельно.

Реальное различие Apple: физическая клавиша 44 даёт `/` и `?` в «Русской», `.` и `,` в «Русской — ПК». Поэтому сценарии ТЗ `ghbdtn? → привет,` и `ghbdtn/ → привет.` используют `ru-pc`; остальные примеры — `ru`. Строки таблиц не подгонялись под примеры.

## Граница симулятора

В 01a нет CGEventTap, AXProbe, реальной инъекции, TISSelectInputSource и проверки внешних приложений. UCPlatformTests подтверждает только отсутствие этих hooks в каркасе. Приложения автоматически не запускались и разрешения им не выдавались.

`InputCoordinator` — детерминированный стенд с виртуальными часами; его trace и полные планы существуют только в памяти для тестового oracle. Они не сериализуются в отчёты. `VirtualField` моделирует шесть типов полей, а не обещает поведение конкретного приложения.

Следующие решения требуют замеров в 01c: точка CGEvent.post, keycode Unicode-вставки, задержки профилей, поведение AX timeout, подтверждение смены источника и поддержка защищённых полей. Чанки сейчас ограничены 20 UTF-16, с парой text-down/text-up и нейтральными модификаторами. Удержанный разделитель сохраняет исходные флаги.

После начала плана он завершается даже при переполнении очереди; неизвестная физическая клавиша до начала переключения отменяет план. Если такая клавиша пришла уже во время исполнения, план завершается, исходное событие пропускается без потери и буфер сбрасывается; счётчик `replayMappingFailures` отмечает этот случай. Поддержка дополнительного источника требует полной таблицы.

## Формат сценариев и воспроизводимость

Сценарии — JSON-подмножество YAML 1.2. Специальные возможности YAML не поддерживаются, ошибки входа возвращаются без содержимого текста. Случайные тесты используют один фиксированный seed и независимый редактор на String, без вызова VirtualField и InjectionPlan.operations.

Swift/LLVM разных версий по-разному считают исполняемые строки: reproduce сравнивает согласованный порог покрытия ≥85%, а точные числитель/знаменатель сохраняет для каждого прогона. Детерминированные счётчики и SHA наборов сравниваются точно.
