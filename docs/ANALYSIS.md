# UltraCorrect 2 — анализ требований, прошлой версии и open source

24.10.2026. В репозитории — `docs/ANALYSIS.md`.
- Метки: **[V]** — проверено по первоисточнику; **[U]** — не подтверждено первоисточником.
- Факты собраны 23–24.10.2026.

## 1. Оценка требований

| Требование | Вывод | Следствие для архитектуры |
|---|---|---|
| Не замедлять при тяжёлой нагрузке | Выполнимо. Нейросеть не может стоять на пути каждого нажатия | Быстрый статистический путь + нейросеть на паузах, энергополитика |
| «На лету» без задержки | Выполнимо для быстрого пути: решение за миллисекунды. Нейросетевые правки — с задержкой в слово | Удержание разделителя, отложенные решения |
| Нейросеть SAGE | Подходит только `sage-fredt5-distilled-95m`: остальные SAGE весят 3–7 ГБ [V]. Точность 83,5% на RUSpellRU [V] — мало для автозамены (нужно ≥98%) | Только как фильтруемое второе мнение (признак решателя) |
| Учиться на лету | Мгновенно — в статистических слоях. Переобучение весов на лету нагрузит ноутбук | §8.6 SPEC; дообучение весов не в 2.0 |
| Любые поля | Невозможно в паролях и при Secure Input [V], в RDP и VM | Профили, статус «пауза» в меню |
| Парные знаки «где ещё нет» | Изнутри чужого приложения надёжно не определяется | Профили по приложениям + переключатель «в этом приложении» |
| «Запустил и работает» | Невозможно полностью: разрешения выдаёт только пользователь, без MDM их не предоставить заранее [V]. Без Developer ID нужно «Всё равно открыть» [V] | Мастер первого запуска, ≤5 действий |
| Другие MacBook | Apple Silicon, macOS 15+ | arm64, постоянная подпись |
| Будущие macOS | macOS 27 вышла 14.09.2026 [U]; панель универсального доступа переименована [U] | Только публичные API, глубокие ссылки, CI на новых образах |

## 2. Прошлая версия 0.1.23: что учтено

**Главные ошибки** (аудит 23.10.2026 по бинарнику и ресурсам, без исходного кода):
1. **Механика на AX.** Замена и проверка опирались на чтение поля через Accessibility.
   - Телемост заблокирован: «текущий доступный редактор не найден» (STATUS 0.1.23).
   - VS Code работал только с `editor.accessibilitySupport=on` и выключенными подсказками.

   Основная часть усилий релизов ушла на совместимость.
2. **Урезанный языковой движок.** Полнота 17,5% на контроле RUSpellRU — это потолок архитектуры:
   - кандидаты только из 42 871 слова;
   - одно слово, левый контекст;
   - отказ при сомнении;
   - нет многословных ошибок и ошибок, дающих реальные слова;
   - нейросеть rubert-tiny v1 без дообучения дала +1 п.п.
3. **Раскладка — список из 308 слов** вместо алгоритма.
4. **«Обучение»** — только личные правила. Нет модели ошибок пользователя и автопорога.
5. **Измерения на 200 примерах** (±5 п.п.). Без личных опечаток и без больших негативов.

**Что сохраняется как принцип:**
- офлайн и отсутствие текста в журналах;
- отказ при сомнении в состоянии поля;
- подтверждённая отмена;
- закреплённые источники с SHA-256;
- тестовые серии.

## 3. Замер Стефании: потолок для клавиатурных опечаток без контекста

`tools/reference/kbd_estimate.py`, 24.10.2026.

**Условия:**
- корректная сторона RUSpellRU test и MultidomainGold test: 6 115 предложений, 110 174 слова ≥3 букв;
- одна синтетическая клавиатурная ошибка на слово, 19 438 ошибок: соседняя клавиша ЙЦУКЕН 40%, пропуск 25%, вставка 20%, перестановка 15%;
- словарь LibreOffice 1,44 млн форм, частоты `ru_full`, кандидаты на расстоянии 1.

| Показатель | Значение |
|---|---|
| Ошибка дала реальное слово | 4,9% |
| Нет кандидатов | 3,5% |
| Верное слово вне словаря | 4,6% |
| Топ-1 верен (нон-слова с кандидатами) | 89,2% |
| Порог 0,98: полнота / точность | 66,5% / 98,3% |
| Порог 0,90: полнота / точность | 73,0% / 96,6% |
| Вред без детектора, порог 0,9 | 12,7 испорченных на 1 000 слов (4,8% верных слов текста нет в словаре) |

**Выводы:**
- Без контекста и детектора цель «≥85% при ≥98,5%» недостижима.
- Нужны:
  - полный лексикон с личным словарём и системным;
  - LM-контекст;
  - детектор «опечатка или незнакомое слово»;
  - личная модель промахов.
- Порог 2.0 в SPEC: ≥85% (цель 90%). Это оценка, её подтверждает или опровергает `uc-eval`.

## 5. Решение по стеку
Swift 6 + SwiftPM. Ядро `UCCore` — чистый Swift: собирается на Linux, поэтому проверяется независимо от Mac.

| Слой | Решение |
|---|---|
| Перехват и вставка | Активный CGEventTap, синтетические события |
| Лексикон | DAFSA (OpenCorpora + LibreOffice) |
| Контекст | 3-граммы (Leipzig + Википедия) |
| Решение | Логистическая регрессия с калибровкой |
| Нейросеть | SAGE-95m через Core ML, rubert-tiny2 как альтернатива; выбор по замеру |
| Сборка ресурсов | Python + uv |
| Оболочка | XcodeGen |
| Обновления | Sparkle 2 |
| CI | GitHub Actions (публичный репозиторий) |

Альтернативы и причины отказа — в SPEC §6.

## 6. Самопроверка анализа
- Все требования пользователя сопоставлены с решением и критерием (SPEC §1.1). Ограничения платформы названы явно.
- Неподтверждённые факты [U] не используются как основание без запасного варианта:
  - зависание при отзыве разрешения → монитор разрешений;
  - переименование панелей → глубокие ссылки;
  - поведение Electron → профили.
- Числа замера Стефании воспроизводимы: скрипт и входные данные указаны.
- Открытые риски:
  1. точность T5 в fp16 на ANE;
  2. фактическая задержка нейросети на M2;
  3. поведение синтетических событий в Телемосте и Telegram Desktop;
  4. достижимость 85% на клавиатурных опечатках.

  Все четыре закрываются замерами в итерациях 1–3.
