# Процесс разработки UltraCorrect 2: ТЗ → релиз → ревью → доработка

Документ живёт в репозитории как `docs/PROCESS.md`. Обязателен для Codex в каждой итерации.

## 1. Роли

| Кто | Что делает | Чего не делает |
|---|---|---|
| **Пользователь** | Передаёт ТЗ в Codex, выдаёт разрешения macOS, по запросу делает ручную проверку в мессенджерах (5–10 мин), пишет Стефании «ревью итерации N» | Не правит код |
| **Codex** (Mac пользователя) | Реализует, тестирует, собирает, публикует ветку, PR и пре-релиз, пишет отчёт | Не меняет спецификацию без согласования, не публикует ничего, кроме описанного ниже, не трогает чужие данные |
| **Стефания** (ВМ, без доступа к Mac) | Архитектура, ТЗ, ревью кода, логов CI и доказательств, ТЗ на доработку и контрольный прогон | Не пишет в репозиторий, не собирает и не запускает код: все прогоны и замеры делает Codex на Mac и CI |

## 2. Цикл итерации

```
ТЗ-NN (Стефания)
  └─► Codex: ветка iter/NN-<slug> → коммиты → CI зелёный → draft PR в main
        → пре-релиз v2.0.0-<stage>.N (DMG + доказательства) → итоговое сообщение
          └─► Пользователь: «ревью итерации NN» (+ свои наблюдения)
                └─► Стефания: REVIEW-NN.md (вердикт) + ТЗ-NN.K на доработку
                      └─► Codex: правки в той же ветке → пре-релиз v2.0.0-<stage>.N.K
                            └─► … пока вердикт не «принять»
                                  └─► Codex по команде пользователя: merge PR, релиз помечается принятым
```

**Нумерация.**
- Итерации: 01a, 01b, 01c, 02, 03, 04, 05 (SPEC §15).
- Доработки: `NN.1`, `NN.2`…
- Версии: номер пре-релиза растёт с каждой итерацией (`2.0.0-alpha.1` … `2.0.0-alpha.5`, `2.0.0-beta.1`, `2.0.0`). Доработка добавляет `.K`: `2.0.0-alpha.3.1`.
- `CFBundleVersion` монотонно растёт с каждой сборкой.
- Итерации без приложения (01a, 01b) публикуют пре-релиз без DMG: отчёт, `evidence.json`, отчёты `uc-sim` и `uc-eval`.

## 3. Правила для Codex

### 3.1. Git и GitHub
- Работа только в ветке `iter/NN-<slug>`. В `main` — только через PR по команде пользователя.
- Следующая итерация начинается от `main` после мержа предыдущей. Если мержа ещё нет — от ветки предыдущей итерации; это указывается в PR.
- Коммиты атомарные, сообщение на английском в повелительном наклонении, с префиксом области (`core:`, `platform:`, `app:`, `tools:`, `eval:`, `ci:`, `docs:`).
- Перед каждым push:
  - `swift build` и все тесты зелёные локально;
  - секрет-сканер чистый: `gitleaks detect`, или аналог, если gitleaks не установлен — указать в отчёте;
  - в индексе нет `work/`, личных данных, ключей, `.p12`, `.mlpackage`, больших ресурсов (>5 МБ).
- Push ветки и draft PR через `gh`. Описание PR = краткий отчёт (§4.2) + ссылка на пре-релиз.
- Пре-релиз: `gh release create v… --prerelease --target <commit ветки>` с ассетами §4.1.
- Запрещено: force-push в `main`, переписывание опубликованной истории, удаление тегов, изменение настроек репозитория — кроме случаев, явно разрешённых пользователем в этой сессии.

### 3.2. Когда останавливаться и спрашивать пользователя
- Операция дольше 30 минут: сборка LM, конвертация модели, загрузка >1 ГБ. Указать оценку времени.
- Нужно действие пользователя: выдать разрешение, ввести пароль Связки ключей, ручная проверка.
- Решение меняет спецификацию или порог приёмки.
- Обнаружены секреты или личные данные в истории.

Во всех остальных случаях — работать автономно до проверенного результата.

### 3.3. Определение «готово» для любой итерации
1. Все пункты ТЗ закрыты или явно помечены «не сделано» с причиной.
2. CI зелёный на последнем коммите ветки (Linux + macOS).
3. Локально пройдены `UCPlatformTests` и smoke по §6; результаты — в `evidence.json`.
4. Если итерация выпускает приложение: DMG собран скриптом, подписан постоянной идентичностью, `codesign --verify --deep --strict` и `spctl -a -vv` (ожидаемо «rejected» без нотаризации — записать вывод) в доказательствах.
5. `docs/iterations/NN/REPORT.md` и `evidence.json` в ветке и в ассетах релиза.
6. Спецификация не нарушена; отклонения — в разделе «Изменения спецификации» отчёта.
7. **Воспроизводимость.** `scripts/reproduce.sh <тег>` с нуля делает чистый клон тега во временный каталог, собирает, запускает тесты, `uc-sim` и (с 01b) `uc-eval`, `uc-bench`, затем сравнивает результаты с `evidence.json` и выводит таблицу «метрика → в отчёте → сейчас → совпало». Сырые выводы всех прогонов (stdout/stderr тестов, отчёты `uc-sim`/`uc-eval`/`uc-bench`, покрытие) упаковываются в `raw-logs-<ver>.tar.gz`. Без пользовательского текста.

## 4. Состав пре-релиза

### 4.1. Ассеты
| Файл | Содержание |
|---|---|
| `UltraCorrect-<ver>.dmg` | Подписанное приложение |
| `SHA256SUMS.txt` | SHA-256 всех ассетов |
| `evidence-<ver>.json` | Машиночитаемые доказательства (§4.3) |
| `REPORT-<ver>.md` | Отчёт (§4.2) |
| `eval-report-<ver>.json/.md` | Начиная с итерации 2 |
| `uc-sim-report-<ver>.json` | Результаты сценариев |
| `raw-logs-<ver>.tar.gz` | Сырые выводы прогонов (§3.3 п. 7) |

### 4.2. `REPORT.md` (шаблон)
```
# UltraCorrect <ver> — итерация NN.K
Коммит: <sha> · Ветка: iter/NN-<slug> · Дата: <ISO> · Модель Codex: <model/effort>

## 1. Итог в 5 строк
## 2. Сделано по пунктам ТЗ (таблица: пункт → статус ✅/⚠️/❌ → где в коде → чем доказано)
## 3. Не сделано и почему
## 4. Метрики (только из прогонов; команда запуска; SHA наборов)
## 5. Производительность (p50/p95/p99, память, CPU; условия замера)
## 6. Совместимость (матрица SPEC §13.4, тип доказательства)
## 7. Изменения спецификации (что, почему, альтернатива)
## 8. Риски и открытые вопросы
## 9. Что нужно от пользователя (конкретные шаги, ≤10 минут)
```

## 5. Протокол ревью (Стефания)

**Вход:**
- пользователь пишет «ревью итерации NN» (или «NN.K»);
- при желании — свои наблюдения.

**Шаги:**
1. Чтение публичного репозитория (`git clone`/`fetch`): `git diff main...iter/NN-<slug>`, PR, CI-логи, ассеты пре-релиза. Сверка SHA-256 ассетов.
2. Сверка с ТЗ по пунктам: заявленное и действительно сделанное.
3. Перепроверка цифр. У Стефании нет Swift, сама она ничего не запускает. Источники проверки:
   - **CI на GitHub** — независим от Mac: `swift test` для `UCCore` и `uc-sim` на Linux и macOS. Сверяю логи запуска с `evidence.json`;
   - **сырые выводы** из `raw-logs-<ver>.tar.gz`: пересчитываю итоговые числа из них (полнота, точность, интервалы, перцентили);
   - **контрольный прогон** для итераций с метриками качества или производительности (с 01b): пользователь запускает **новую** сессию Codex (gpt-6-luna, effort low) с ТЗ `VERIFY-NN.md` от Стефании: выполнить `scripts/reproduce.sh <тег>` и выложить вывод. Новая сессия не видит контекст разработки и не может подогнать результат под отчёт.

   Расхождение с отчётом больше погрешности прогона — блокер.
4. Чек-лист:

   | Область | Что проверяю |
   |---|---|
   | Архитектура | `UCCore` без AppKit; нет логики в UI; нет «заплаток под слова» |
   | Безопасность ввода | Удержание ввода, отказ при сомнении, окно отмены, Secure Input, защита от зависания (§7.1) |
   | Приватность | Нет текста в `print`/`os_log`/файлах/отчётах; нет сети вне Sparkle |
   | Тесты | Покрывают сценарии ТЗ; негативные случаи; нет отключённых тестов без причины |
   | Метрики | Воспроизводятся; test заморожен; нет подгонки; интервалы |
   | Производительность | Бюджеты §11, условия замера честные |
   | Ресурсы | Лицензии, SHA, notices |
   | Сборка | Подпись одной идентичностью, DMG ставится, версия растёт |
   | Документация | REPORT по шаблону, PLATFORM-NOTES обновлены |

5. Выход — `REVIEW-NN.K.md`:
   - вердикт: **принять** / **доработать** / **переделать**;
   - замечания с уровнем:
     - **Блокер** — нарушает безопасность, приватность, ТЗ, бюджет или ломает сборку;
     - **Важное** — снижает качество, нужно в этой итерации;
     - **Улучшение** — можно позже;
   - для каждого замечания: файл:строка, суть, как проверить исправление.
6. Если вердикт не «принять» — ТЗ-NN.K+1: только замечания, критерии готовности, запреты. Если «принять» — ТЗ следующей итерации.

**Что пользователь получает от меня:**
- вердикт в 3–5 строк;
- путь к REVIEW-файлу;
- путь к следующему ТЗ;
- рекомендуемые модель и effort для Codex.

## 6. Правила проверки в реальных приложениях (smoke)
- **Кто нажимает клавиши.** Синтетический набор выполняет драйвер внутри `UCTestHost` — наше подписанное приложение с собственным разрешением «Универсальный доступ». Терминалу и Codex это разрешение не выдаётся. Codex запускает драйвер командой (`open -a UCTestHost --args --smoke <сценарий> --report <файл>`).
- **Перед каждой серией** драйвер проверяет, что на переднем плане нужное приложение и нужное окно. Если пользователь нажал реальную клавишу во время серии — серия прерывается. Codex заранее просит пользователя не печатать во время прогона.
- **Проверка результата** — только по своему тексту:
  - Obsidian — файл заметки тестового vault;
  - VS Code — сохранённый файл в `/tmp/uc-smoke`;
  - нативные приложения — AX-значение поля, если доступно;
  - иначе — ручная проверка пользователем (§7).
- **Скриншоты** — только окон `UCTestHost` и самого UltraCorrect (меню, мастер, настройки). Окна чужих приложений не снимаются и не публикуются.
- Только собственные пустые черновики или файлы, созданные для теста:
  - Telegram — «Избранное»;
  - VS Code — новый файл в `/tmp/uc-smoke`;
  - Obsidian — отдельный тестовый vault;
  - браузер — локальная страница `Tests/Smoke/page.html`.

  После теста очистить.
- В мессенджерах и ChatGPT **никогда** не нажимать Enter и не отправлять сообщения автоматически. Сценарий «перед Enter» проверяется только в `UCTestHost` и на локальной странице. В мессенджерах его проверяет пользователь вручную по чек-листу из REPORT §9.
- Не читать и не сохранять существующий текст полей. Если поле не пустое — тест в нём не выполняется.
- Обучение во время тестов — только во временном хранилище (`UC_DATA_DIR`), личные данные пользователя не меняются.
- Каждый результат — в `compatibility` с версией приложения и типом доказательства.

## 7. Ручной чек-лист пользователя (≤10 минут, после каждой итерации с изменениями механики)
1. Telegram, «Избранное»: набрать «превет как дила» + пробел → «привет как дела». ⌘Z → «дила» вернулось. Стереть.
2. Тот же черновик: «ghbdtn» + пробел → «привет», раскладка стала русской.
3. ChatGPT (приложение): `[` → `[]`, затем `]` — курсор перепрыгнул.
4. Телемост (чат встречи или тестовая встреча): пункт 1 без отправки.
5. Obsidian: `[` — скобка одна, от Obsidian, без второй от UltraCorrect.
6. Иконка: пауза и снятие паузы работают.

Результат одной строкой «1✅ 2✅ 3❌(…)» — в сообщении Стефании вместе с «ревью итерации NN».
