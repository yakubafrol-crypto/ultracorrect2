# ТЗ-01a для Codex: UltraCorrect 2 — подготовка репозитория и ядро механики ввода

Версия: 2.0.0-alpha.1 · Ветка: `iter/01a-core-mechanics` · Пре-релиз без DMG

## 0. Роль, цель, входные материалы

Ты — ведущий инженер macOS-приложения **UltraCorrect 2**. Это новая реализация с нуля: приложение в строке меню, которое во время набора в любых приложениях:
- исправляет русские опечатки;
- меняет ошибочную раскладку EN→RU;
- ставит парные `[] {} ""`.

Код пишешь ты. Архитектор и ревьюер — Стефания: она проверяет результат по публичному репозиторию, логам CI и опубликованным артефактам. Сама она ничего не собирает и не запускает, поэтому все прогоны и замеры выполняешь ты на Mac и в CI, а сырые выводы публикуешь (PROCESS §3.3, §4.1).

**Цель 01a** (SPEC §15):
1. безопасно подготовить репозиторий к публикации;
2. поставить каркас, CI и постоянную подпись;
3. реализовать и доказать на симуляторе **чистую логику механики**: буфер ввода, границы слов, токены английской раскладки, окно отмены, пары, планы замены.

Платформенного кода (перехват, вставка), приложения и DMG в этой итерации нет — это 01c.

## 1. Неприкосновенные ограничения (действуют во всех итерациях)

1. **Приватность** (SPEC §10). Текст пользователя никогда не попадает в журналы, отчёты, Git, сеть, сообщения ошибок. Это касается и тестов.
2. **Безопасность ввода** (SPEC §2.1, §7). Набор пользователя не теряется, не дублируется, не переставляется. При сомнении — отказ от замены. Начатый план исполняется до конца (SPEC §7.5.2).
3. **AX не основа** (SPEC §2.5). Насильно включать AX в чужих приложениях запрещено.
4. **Git** — по PROCESS §3.1. Не мержить в `main` и не менять настройки и видимость репозитория без явного подтверждения пользователя в этой сессии.
5. **Никаких заплаток под отдельные слова** в коде — только данные с источником.
6. **Лицензии.** Каждый внешний ресурс — с URL, SHA-256 и лицензией в `Resources/manifest.json` и `docs/THIRD_PARTY_NOTICES.md`.
7. **Не менять** глобальные настройки macOS и других приложений.
8. **Честный отчёт** (SPEC §2.6).

### Шаг 0. Подготовка репозитория к публикации [СТОП в конце]
1. **Сохрани старую версию:** тег `legacy-0.1.23` на текущем `main` и ветку `legacy/0.1`, если их ещё нет.
2. **Аудит перед публикацией.** Пользователь решил сделать репозиторий публичным. После этого станут публичными вся история, все ветки, теги, Releases с ассетами, Issues, PR (включая `refs/pull/*`), Wiki, логи и артефакты Actions.

   Проверь:
   - `gitleaks detect --log-opts="--all"` по всей истории (установи через Homebrew, если нет);
   - поиск по всей истории файлов типов `*.p12 *.cer *.key *.pem *.mobileprovision *.env *.sqlite *.db *.plist` из `Application Support`, хранилищ обучения, корпусов личных опечаток, журналов;
   - **ручной просмотр** отчётов, STATUS-файлов, тестовых данных и скриншотов (`*.png`, `*.jpg`) на предмет личного текста пользователя: переписка, черновики, его реальные опечатки. Gitleaks такое не находит;
   - ассеты существующих Releases, тексты Issues и PR, артефакты Actions.
3. Результат запиши в `history-audit.md` **локально, вне Git**: `work/history-audit.md` (каталог `work/` в `.gitignore`). В файле только пути, коммиты и типы находок, без содержимого.
4. **[СТОП]** Сообщи пользователю итог:
   - **Чисто** → скажи, что репозиторий можно сделать публичным. Видимость меняет пользователь либо ты по его явному «да»: `gh repo edit --visibility public --accept-visibility-change-consequences`.

5. **Зафиксируй наследие** в `docs/iterations/01a/legacy-notes.md` (этот файл можно публиковать, без личных данных):

   - bundle id;
   - имя и SHA-1 идентичности подписи 0.1.x и есть ли она в Связке ключей;
   - путь к `normative.utf8` в теге `legacy-0.1.23`.

**Готово:**

- аудит выполнен;
- пользователь решил вопрос публичности;
- `legacy-notes.md` есть.

### Шаг 2. `UCCore`: автоматы механики (чистая логика, Linux)
Реализуй по SPEC §7.3–§7.7 и §8.5 (только конверсия и токенизация, без детектора):

| Тип | Назначение |
|---|---|
| `KeyEvent` | Символ, keycode, флаги, тип (down/up/flags/mouse/focus/secureInput), источник ввода, время, признак своего события. Без CoreGraphics |
| `KeyLayoutMap` | Протокол «keycode+модификаторы → символ»; реализация из `Tests/Fixtures/layouts/*.json` |
| `TypingSession` | Буфер ≤400 символов с физическими клавишами, эпохи, `leftBoundaryKnown`, белый список сочетаний (§7.3), токены русской и английской раскладки по физическим клавишам, мягкий триггер `.`, исключения §7.4. На событие возвращает действия: `pass, hold, swallow, trigger, softTrigger, revert, pairInsert, pairOvertype, pairDelete, manualFix` |
| `RevertWindow` | Окно отмены §7.6, журнал последних 3 планов |
| `AutoPair` | Автомат пар §7.7, включая удаление нашего закрывающего знака при конверсии раскладки |
| `LayoutConverter` | Конверсия токена EN↔RU по физическим клавишам |
| `InjectionPlan` | Структура §7.5.1 (`deleteBackward`, `deleteForward`, `insert`, `trailing`, `then`, `before/after`, источники ввода) и построение планов: замена, отмена, пары, конверсия раскладки, ретроактивная замена §7.5.3 |
| `CorrectionEngine` | Протокол движка: вход — токен, контекст, профиль; выход — `replace`/`defer`/`keep` |
| `StubLayoutEngine` | Временный движок для симуляций: конвертирует токены из фиксированного тестового списка. Настоящий детектор — в 01b |
| `VirtualField` | Модель поля для симуляции, 6 видов (SPEC §13.3): простое; само ставит пары; автодополнение по Enter; встроенное автодополнение с выделением; теряет быстрые Backspace; системные подстановки |

**`uc-sim`:**
- читает `Tests/Scenarios/*.yaml`: события с таймингами + вид поля + профиль + движок + ожидаемый итоговый текст, действия и источник ввода;
- прогоняет через `TypingSession` → `InjectionPlan` → `VirtualField`;
- выдаёт `uc-sim-report.json`.

Время инъектируемое, результат детерминирован.

**Сценарии:** обязательны все из SPEC §13.3 (включая расширенный список) плюс ниже, всего ≥80.

Механика и отмена:
- замена по каждому разделителю;
- Enter при `correctBeforeEnter=true/false`;
- `triggers=spaceOnly`;
- удержание: ввод во время решения и во время плана — исходный порядок, keyUp и flagsChanged тоже;
- переполнение очереди до начала плана — отказ без потерь;
- таймаут решения 25 мс — разделитель без изменений;
- ⌘Z в окне — `before` восстановлен; вне окна — проход и сброс;
- двойной ⇧ по только что исправленному слову и по предпоследнему — отмена; двойной ⇧ по латинице — конверсия; повтор — исходное;
- Backspace-откат (опция).

Границы и сброс:
- щелчок посреди слова, смена фокуса, Tab, ⌘L, ⌘T, Fn/🌐, переключение Secure Input → сброс и нет замены до известной границы.

Пары:
- `[`, `{`, `"` после пробела и внутри слова;
- перешагивание;
- удаление пустой пары;
- навигация забывает пары;
- поле «ставит пары само» + профиль `pairs=false` → ничего.

Исключения:
- §7.4: URL, e-mail, `@`, `#`, цифры, `_`, camelCase, обратные кавычки, ВСЕ ЗАГЛАВНЫЕ, мягкий `.` (`сайт.рф`, `т.е.`).

Раскладка (с `StubLayoutEngine`):
- `ghbdtn␠→привет␠`;
- `Ghbdtn→Привет`;
- `[jhjij␠→хорошо␠`;
- `"nj␠→Это␠` (автопара удаляется);
- `ghbdtn?␠→привет,␠`;
- `yt pyf␠→не знаю␠`;
- удержанные нажатия пересчитаны под новый источник;
- ⌘Z возвращает текст и источник.

Прочее:
- зажатый ⌘/⌥/⇧ во время плана;
- поле с выделением подсказки — отказ;
- поле с системной автозаглавной — проверка расхождения;
- IME-источник — коррекция выключена;
- повтор клавиши.

**Свойство-тесты** (property-based или рандомизированные с фиксированным seed), 10 000 случайных потоков событий через `VirtualField` «простое» при движке «ничего не менять» и движке-заглушке:
- (а) итоговый текст поля равен тексту, который получился бы без UltraCorrect, плюс только запланированные замены;
- (б) ни одно пользовательское событие не потеряно и не переставлено.

**Готово:**
- все сценарии и свойство-тесты проходят на Linux (CI) и macOS;
- покрытие строк `UCCore` ≥85% (`swift test --enable-code-coverage`, число в отчёт).
