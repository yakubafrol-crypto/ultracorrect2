## 3. Не сделано и почему

- Перехват, AXProbe, реальная инъекция, TISSelectInputSource, полноценный UI, разрешения, smoke в приложениях и DMG — явно исключены из 01a, будут в 01c.

- Создание нового сертификата не выполнялось: имеется требуемая постоянная идентичность. Typecheck помощника прошёл; повторное использование и подпись существующим ключом проверены.
- Полный ручной аудит старой истории остановлен после личных данных, как требовало ТЗ. Старый репозиторий не публиковался; его аудит не объявляется «чистым».

Команды: `swift build`; `swift test --enable-code-coverage`; `swift run uc-sim --report work/uc-sim-report.json`; `python3 scripts/coverage.py --minimum 85`.

Каждый случайный поток начинается синтетическим контрольным токеном, затем содержит случайные символы, навигацию, модификаторы, фокус и разделители; длина 20–59 событий. Oracle использует собственный String-редактор. Он проверяет, что исходный участок совпадает с `before` плана (с учётом удержанного разделителя), применяет заявленную замену, сравнивает итоговый текст и курсор; отдельно проверяются порядок и полнота пользовательских ID. VirtualField и низкоуровневые операции плана в oracle не вызываются. Все данные синтетические/из ТЗ.

SHA наборов и всех файлов реализации — в `evidence.json`. Счётчики/хеши воспроизводятся точно. Между Swift/LLVM может отличаться число исполняемых строк, поэтому переносимый критерий воспроизведения — покрытие ≥85%; числитель и знаменатель каждого прогона сохраняются отдельно. `commit` во встроенном evidence — базовый проверенный коммит реализации; после формирования доказательств идут только документальные коммиты. Неизменность кода проверяют implementation_hashes.

Чистое воспроизведение: `UC_REPRODUCE_REPOSITORY=<локальный Git-репозиторий> scripts/reproduce.sh v2.0.0-alpha.1`. Использован новый временный клон с `--no-local`, без рабочего дерева и кэша `.build` исходного checkout. Все 68 строк сравнения — «совпало». В публичном режиме тот же скрипт клонирует GitHub по умолчанию. Подробная таблица и отдельные build/tests/sim/coverage логи включены в raw-logs. Подпись пустых приложений проверяется отдельно через `build.sh`.

CI релизного коммита независимо подтвердил 142/142 сценария, одинаковые счётчики property-прогона и покрытие ≥85% на всех трёх runner. Подробные значения по runner — в `ci_metrics` evidence; сырые выводы прилагаются.

## 7. Изменения спецификации и принятые решения

Согласовано пользователем:

- После аудита — новый публичный `yakubafrol-crypto/ultracorrect2`, старый остаётся приватным.
- При противоречии §7.3/§7.7 пары ставятся сразу по §7.7; конверсия удаляет принадлежащее нам автозакрытие.
- Для «не знаю» тестовый ввод исправлен на `yt pyf.`; отдельный тест сохраняет физически точное `yt pyf → не зна`. Входные документы не изменены.

Выбрано в пределах реализации:

- YAML 1.2 используется в его JSON-подмножестве, без внешнего парсера.
- Примеры со slash/question используют реальную «Русскую — ПК»: на Apple «Русской» keycode 44 имеет другие символы. См. PLATFORM-NOTES.
- Короткий EN-токен определяется по числу букв результата физической конверсии: кавычка в `"nj` является физической русской буквой, поэтому токен не считается двухбуквенным.
- При неизвестной клавише в удержанной очереди до начала конверсии — отказ. Если она пришла после начала, план завершается, событие сохраняется в исходном виде, буфер сбрасывается и увеличивается счётчик. Это безопасная деградация неполной таблицы, не обещание корректного текста для неподдерживаемого источника.

## 8. Риски и вопросы к ревью

- Симулятор доказывает свойства модели, а не надёжность CGEvent/AX в чужих приложениях. Полноценные UCPlatformTests ещё нужны в 01c.
- Вопрос к ревью: достаточно ли выбранной деградации для отсутствующего physical mapping после старта, или в 01c нужно ограничить поддерживаемые клавиатуры ещё до активации коррекции.
- Вопрос к ревью: при AX timeout общий профиль продолжает без AX, а inlineCompletion отказывается. Это трактовка штатной недоступности AX; платформенный замер может потребовать более консервативного профиля.
- Immutable-тег `v2.0.0-alpha.1` указывает на `8f3213b945589a740c368405e6f454e0d6d3aa19`. В теге лежит baseline evidence для сравнения. Итоговые доказательства добавлены отдельным документальным коммитом в ветку и в ассеты релиза после прогона. Код тега и ветки одинаков по implementation_hashes; тег не перемещался.
